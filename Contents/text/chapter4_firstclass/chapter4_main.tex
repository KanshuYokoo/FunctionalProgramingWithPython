\chapter{Functions as First-Class Citizens}

\section{What Does ``First-Class'' Mean?}

In many traditional programming languages, functions and data are kept strictly separate. You can store an integer in a variable, pass a string to a function, or return a boolean. But you cannot do those things \textit{with a function itself}. The function is a static piece of architecture, while the data flows through it.

In functional programming, \textbf{functions are data}. 

When we say a language treats functions as ``First-Class Citizens,'' we mean that a function has the exact same rights and privileges as any other piece of data (like an integer or a string). Specifically, you can:
\begin{enumerate}
    \item Assign a function to a variable.
    \item Pass a function as an argument to another function.
    \item Return a function as the result of another function.
\end{enumerate}

\subsection{The Categorical View: Morphisms and Exponential Objects}

To truly appreciate what it means for a function to be data, we can look to \textbf{Category Theory}, a branch of mathematics that serves as the theoretical foundation for functional programming. 

In Category Theory, a category consists of two primary constructs:
\begin{itemize}
    \item \textbf{Objects}: In programming, you can think of these as data types (e.g., \texttt{Integer}, \texttt{String}, \texttt{Boolean}).
    \item \textbf{Morphisms}: These are the ``arrows'' or mappings between objects. In programming, a morphism from object $A$ to object $B$ is simply a function that takes an argument of type $A$ and returns a value of type $B$ (written mathematically as $f: A \to B$).
\end{itemize}

Normally, objects and morphisms are distinct concepts. Objects are the ``things,'' and morphisms are the ``actions'' between those things. 

However, functional programming languages (specifically those whose type systems form a \textit{Cartesian closed category}) introduce a profound concept called an \textbf{exponential object} (sometimes called an internal hom-object). 

An exponential object, often denoted as $B^A$ or $A \Rightarrow B$, takes the entire set of morphisms (functions) from $A$ to $B$ and groups them into \textit{a brand new object within the category itself}. 

When a category has exponential objects, it means that the ``action'' (the morphism) has been crystallized into a ``thing'' (an object). Because the function $A \to B$ is now recognized mathematically as an object $B^A$, it gains all the fundamental rights of any other object. You can draw new arrows (write new functions) that take $B^A$ as an input, or that return $B^A$ as an output. 

This categorical abstraction is the exact mathematical equivalent of treating functions as first-class citizens in code. It tells us that functions are not just invisible pipelines moving data---they are tangible data themselves, ready to be stored, passed, and manipulated.

\section{Higher-Order Functions}

A function that does at least one of the following is called a \textbf{Higher-Order Function} (HOF):
\begin{itemize}
    \item Takes one or more functions as arguments.
    \item Returns a function as its result.
\end{itemize}

Calculus students might recognize this concept. The derivative operator $\frac{d}{dx}$ is a higher-order function: it takes a function as an input (like $f(x) = x^2$) and returns a new function as an output ($f'(x) = 2x$).

\subsection{A Mathematical Example: Summation}

To gain a deeper insight into the power of Higher-Order Functions, let us look at a fundamental mathematical concept: summation. 

In mathematics, the summation of a series is written as:
\[ \sum_{n=a}^{b} f(n) \]
where $a$ is the lower bound, $b$ is the upper bound, and $f(n)$ is a function that defines the term for each step $n$.

Notice how the summation operator $\sum$ behaves. It is not computing a simple value; it is a higher-level operator that requires a function $f(n)$ to be passed into it. If we choose $f(x) = x^2$, the summation computes $1^2 + 2^2 + 3^2 + \dots$. If we choose $f(x) = x^3$, it computes $1^3 + 2^3 + 3^3 + \dots$. 

Mathematically, the summation operator $\sum$ is a Higher-Order Function with the following signature:
\[ \sum : (\mathbb{Z} \to \mathbb{Z}) \to \mathbb{Z} \to \mathbb{Z} \to \mathbb{Z} \]
It takes a function (mapping an integer to an integer), the starting integer bounds, and returns a single summed integer. 

We can translate this mathematical concept directly into Python code. By treating the function $f$ as a first-class parameter, we can write a highly generalized summation function.

\paragraph{Function Spaces, Functionals, and Operators}

Mathematically, Higher-Order Functions are formalizations of mappings on \textbf{function spaces}. If $A$ and $B$ are sets, we can define the set of all functions from $A$ to $B$ as a new set, denoted as $B^A$ (or $A \to B$). 

By treating function spaces as first-class mathematical spaces, we can construct functions that act on these spaces. Pure mathematics classifies these higher-order transformations into two main categories:
\begin{enumerate}
    \item \textbf{Functionals}: A functional is a function that takes one or more functions as arguments and returns a scalar (a primitive value like a real number or an integer). For example, the definite integral $\int_{a}^{b} f(x)\,dx$ is a functional: it takes a continuous function $f$ in the function space $C[a, b]$ and collapses it down to a single real number. Similarly, our summation function $\sum_{n=a}^{b} f(n)$ is a functional. In programming, reducing or folding a list (like computing a sum or product) behaves like a functional.
    \item \textbf{Operators}: An operator is a function that takes a function as an argument and returns another function. For example, the derivative operator $D(f) = f'$ maps a differentiable function to its derivative function. In functional programming, function composition, currying, or functions like \texttt{map} (when partially applied) act as operators because they yield new function pipelines rather than final values.
\end{enumerate}

This taxonomy bridges the gap between software engineering and classical analysis. When you write a Higher-Order Function, you are not merely organizing code; you are building mathematical functionals and operators on function spaces.

\subsection{Returning Functions as Results: Operators}

So far, we have focused on Higher-Order Functions that take functions as arguments. However, the second half of the HOF definition is equally powerful: \textbf{functions that return other functions as their results}. 

In pure mathematics, functions that map functions to other functions are often called \textbf{operators}. When a programming function returns a function, it acts as a factory or an operator, producing a new, customized behavior that can be executed later.

Let us explore this concept through two fundamental examples: numerical differentiation and function composition.

\subsection{Currying and Partial Application}

Another crucial concept that relies on returning functions is \textbf{Currying}, named in honor of the logician Haskell Curry (and independently discovered by Moses Schönfinkel). Currying is the technique of converting a function that takes multiple arguments into a chain of functions that each take a single argument.

\paragraph{Mathematical Foundation: Product Spaces and Function Spaces}

To understand currying, we must first define two core mathematical concepts:
\begin{itemize}
    \item \textbf{Product Space}: If we have sets $A$ and $B$, their Cartesian product $A \times B$ is the set of all ordered pairs $(a, b)$. A traditional function of two variables accepts its arguments as a single pair from this product space:
    \[ f : (A \times B) \to C \]
    In programming, this corresponds to passing a tuple of arguments, such as \texttt{f(x, y)}.
    \item \textbf{Function Space (Exponential Object)}: In set theory, the set of all functions mapping from a set $B$ to a set $C$ is written as $C^B$ (read as ``$C$ to the power of $B$'' or simply the function space $B \to C$). 
    The exponential notation is highly intuitive: if $B$ and $C$ are finite sets, the total number of unique functions from $B$ to $C$ is exactly $|C|^{|B|}$. In programming, $C^B$ represents a function type signature, such as a function that expects an argument of type $B$ and yields a result of type $C$.
\end{itemize}

\paragraph{The Product-Exponential Adjunction: Step-by-Step}

Mathematically, currying asserts that the set of functions on a product space is isomorphic (has a one-to-one correspondence) to the set of functions returning functions. This is written exponentially as:
\[ C^{A \times B} \cong (C^B)^A \]

Let us break down why this is true step-by-step:
\begin{enumerate}
    \item \textbf{Step 1: The Product-Based Function (Uncurried)}:
    Consider a function $f : A \times B \to C$. It expects a pair $(a, b)$ all at once. Once both values are provided, it yields a result $c \in C$:
    \[ f(a, b) = c \]
    \item \textbf{Step 2: The Nested Function (Curried)}:
    Now consider a function $g : A \to C^B$. It accepts only a single element $a \in A$, and returns a function $h_a : B \to C$. This returned function $h_a$, when subsequently given $b \in B$, yields the final result $c \in C$:
    \[ g(a)(b) = h_a(b) = c \]
    \item \textbf{Step 3: The Translation (Curry \& Uncurry)}:
    Because $f$ and $g$ represent the exact same relationship between the inputs and output, we can translate between them without losing any information:
    \begin{itemize}
        \item To turn $f$ into $g$ (currying), we define: $g(a) = (b \mapsto f(a, b))$.
        \item To turn $g$ into $f$ (uncurrying), we define: $f(a, b) = g(a)(b)$.
    \end{itemize}
    \item \textbf{Step 4: The Adjunction Formality}:
    In Category Theory, this bijection is formalized as the \textbf{Product-Exponential Adjunction}:
    \[ \text{Hom}(A \times B, C) \cong \text{Hom}(A, C^B) \]
    This adjunction states that the product functor $(-\times B)$ is left adjoint to the exponential functor $(-)^B$. It guarantees that any multi-argument function can be modeled as a single-argument higher-order function returning another function.
\end{enumerate}

\subsection{Map, Filter, and Reduce}

Because functional programmers use Higher-Order Functions constantly, three specific HOFs have become the universal standard for processing lists of data: \texttt{map}, \texttt{filter}, and \texttt{reduce} (often called \texttt{fold}).

\subsubsection{Map}
\texttt{map} takes a function and a list, and applies that function to every single item in the list, returning a new list.

If you have a list of integers \texttt{[1, 2, 3]} and you \texttt{map} a square function over it, you get \texttt{[1, 4, 9]}. You never write a \texttt{for}-loop; you just declare the transformation.

\subsubsection{Filter}
\texttt{filter} takes a \textit{predicate} function (a function that returns True or False) and a list. It returns a new list containing only the items for which the predicate returned True. 

If you \texttt{filter} the list \texttt{[1, 2, 3, 4]} with an \texttt{is\_even} function, you get \texttt{[2, 4]}.

\subsubsection{Reduce (Fold)}
\texttt{reduce} (or \texttt{fold} in Haskell) takes a function, an initial starting value, and a list. It uses the function to combine the elements one by one until the list is reduced to a single value.

For example, reducing the list \texttt{[1, 2, 3]} with an addition function and a starting value of $0$ will compute $(((0 + 1) + 2) + 3) = 6$.

\section{A Gentle Introduction to Functors}

In Category Theory, we established that a Category consists of Objects (types) and Morphisms (functions). 

What happens if we want to map relationships \textit{between entire categories}? 

In Category Theory, a mapping between categories is called a \textbf{Functor}. In programming, you can think of a Functor as any container or context (like a List) that can be mapped over. 

When you use the \texttt{map} function on a List of Integers to turn it into a List of Strings, you are using the List Functor. The Functor reaches inside the container, applies your function to the data, and wraps the results back up in a new container, all while preserving the structure of the container itself. 

Functions as first-class citizens are what make concepts like Functors possible in code. By passing a function into \texttt{map}, you are lifting that simple data transformation into a higher mathematical dimension.
